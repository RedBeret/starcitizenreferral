Essential ship controls: keys, doors and staggered fire.

Start with a small set of useful actions, then bind and test door or weapon controls in the right context.

By PatchOpsSources checked 15 November 2026Independent community guide
Quick answer

Learn a few actions first: interact, contact ATC, lower the gear, brake and inspect the ship with the camera. Then add clearly separated door and weapon-mode bindings. For a single door, start with its local control rather than assuming a ship-wide command selects only that door.

Essential keys to recognize first

These are defaults documented in RSI’s first-flight instructions and landing guide, not a live export of your profile. Check your current Keybindings screen before relying on a key; imported profiles and later changes can differ.

ActionDocumented defaultHow to use it
InteractFLook at the relevant panel or object and use its interaction prompt.
Contact ATCLeft Alt + NRequest clearance near the facility, then read the response.
Landing gearNCheck the gear state before approach or departure.
Space brakeXLearn the braking action in clear space before a close approach.
Third-person cameraF4Inspect the ship’s surroundings and clearance.
mobiGlasF1Open its apps, including services once appropriately landed.

Keep action names in your notes alongside the keys. If a shortcut changes, “contact ATC” still tells you what to find. A key alone does not tell you whether you are in the right seat, mode or interaction context.

Set up the extra actions you actually need

  1. Open Options → Keybindings and select the device you are editing.
  2. Open Advanced Controls Customization.
  3. Expand the relevant vehicle category and inspect its available actions.
  4. Select an action, read its current assignment and bind an unused input.
  5. Read any conflicts, then test one action before adding the next.

RSI’s binding instructions describe double-clicking to capture an input and right-clicking to unbind. Do not copy somebody’s custom shortcut and assume it is a factory default. The profile guide covers exporting your working setup.

Open all doors, close all doors and door locks

In the vehicle cockpit actions, look for the available door controls: Open All Doors, Close All Doors, an open/close toggle, and lock/unlock actions. Wording and grouping can vary, so match the action shown by your installed game.

Control typeWhat to distinguish
Open / closeThe physical state of the doors affected by that command.
Lock / unlockAccess permissions; unlocking is a different task from opening.
Separate open and close actionsAn explicit requested state.
ToggleA state change; inspect the result before pressing it again.

Suggested setup: if separate open and close actions are available, assign two distinct inputs you have checked for conflicts. Keep locking on a separate binding. These are layout suggestions, not universal preset keys.

Test while stationary with another player watching which doors actually move. A broad door action is a poor substitute for checking the exact opening you need. Ship access, seat context and implementation can affect the result.

Staggered fire: what it means and how to find it

Staggered fire spaces weapon shots rather than delivering the same simultaneous volley. RSI’s turret explanation describes the underlying tradeoff in shot distribution and damage per volley. It is useful background, not a current default-key chart.

Look in the vehicle weapon actions for the staggered-fire control; inspect any separate turret actions if you are configuring a gunner seat. Bind the available toggle or explicit state action, check conflicts, and test from the seat where you intend to use it. Do not assume a pilot binding configures every turret context.

Compare the firing rhythm using the same weapon group and loadout in an appropriate practice setting. A different rhythm is not proof of greater total damage. If nothing changes, check whether the input registered, the active seat and weapon group, and whether that setup supports a visible difference.

One door instead of every door

First identify the opening: an exterior ramp, internal passage, cargo lift or onboard hangar door. Use the labelled local panel where available. For ships with an engineering console, inspect its room and door controls rather than treating every opening as the same cockpit action.

RSI’s engineering guide describes a room-by-room readout including door states. Check the current console for the particular ship and confirm the physical result; a visible state readout and a dedicated keyboard binding are different things.

Galaxy: a single-door control is not established here

For a Galaxy task, name the exact opening before configuring anything: the rear hangar door, an internal passage, or a module-related opening. That prevents “open the door” from meaning different things to the pilot and the person waiting beside it.

I have not verified a dedicated Galaxy single-door keyboard action in the official material reviewed for this guide. Do not treat an all-doors binding as a confirmed solution for one selected Galaxy door, or ATC clearance as a confirmed remote control for its onboard hangar.

Use the labelled local control or inspect the ship’s current console options, with someone watching the intended opening. If your controls list offers a specific action, record its exact name, seat and observed result before saving the binding. This section does not promise a particular panel location or an unsupported shortcut.

Save a small setup you understand

After testing, export the profile and keep a short action-to-key note. Include any seat-specific behavior you observed. Before a real trip, use the departure checklist; for the actual ATC approach, follow the landing walkthrough.
