The pilot’s field guide

Write a bug report another player can reproduce.

Describe what happened, show the steps and keep observations separate from guesses about the cause.

By PatchOpsSources checked 15 November 2026Independent community guide
Quick answer

Search the official Issue Council before creating a bug report. Match the actual symptoms and reproduction steps, then contribute evidence or create a focused report. State what you observed separately from what you think caused it.

On this page
  • Choose the right destination
  • Search by object, action and situation
  • Record a small, observable sequence
  • Use this report outline
  • Contribute without overstating the result

Choose the right destination

RSI’s Issue Council guide directs game bugs to the Issue Council. Design suggestions and balance opinions belong on Spectrum. A report about a feature failing should explain the failure, rather than only whether you like the feature.

If you need help understanding a mechanic, a player guide can help distinguish an unfamiliar step from an apparent fault. You do not need to prove the underlying software cause to describe a reproducible problem.

Search by object, action and situation

The official search guide recommends describing the thing affected, what happened and where or when it happened. Try both the exact ship or item name and a broader term. Read a candidate report’s steps before deciding it is the same issue.

For example, “inventory item disappears after move” is more useful than “broken game.” Change one part of the search if results describe a different situation. An existing active report may accept a contribution from a newer build; do not create a duplicate merely because its original version is older.

Record a small, observable sequence

  1. Note the environment and full build identifier you used.
  2. Record the location, ship or item involved.
  3. List the actions immediately before the failure.
  4. Separate the actual result from the expected result.
  5. Attach an image or short video that shows the relevant step.

If it happened once, say once. If you tried three times and saw it twice, report those counts. “Always” and “never” are stronger claims than a single session supports. If you found a workaround, record it as something you observed, not a guaranteed fix.

Keep one report about one problem. A concise title and a short reproduction sequence help another player decide whether they can confirm it.

Contribute without overstating the result

Follow the report’s status and the current Issue Council instructions. Add new evidence when it clarifies the same issue. A report being confirmed does not promise a particular fix date.

For exploits or account-sensitive findings, RSI documents a dedicated Exploit / Account Issue category that limits public exposure. Follow that route instead of posting sensitive details into a normal public report.
